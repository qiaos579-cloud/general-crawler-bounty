# 给 Codex 的第一批开发任务

建议按下面顺序逐项完成，不要一开始做复杂前端。

## P0：先把闭环做稳定

- [ ] 为 `TaskService` 增加持久化任务存储，优先 SQLite；
- [ ] 增加任务列表接口：`GET /tasks`；
- [ ] 增加任务状态筛选；
- [ ] 增加请求失败重试（只处理正常网络错误和 5xx，不规避访问控制）；
- [ ] 增加最大正文长度和响应大小限制；
- [ ] 增加域名级并发限制，避免对目标站点造成过大压力；
- [ ] 为 HTML / JSON 采集器补充单元测试与 mock HTTP 测试；
- [ ] 增加结构化错误码。

## P1：增强通用性

- [ ] 增加批量 URL 提交；
- [ ] 增加 YAML 任务配置；
- [ ] 增加站点采集器模板 `collectors/template.py`；
- [ ] 增加 robots.txt / 站点采集规则检查提示；
- [ ] 增加正文提取器接口；
- [ ] 增加字段映射器；
- [ ] 增加 CSV / JSON 导出；
- [ ] 接入 SQLite/PostgreSQL Storage Adapter。

## P2：扩展动态页面

- [ ] 增加可选 Playwright 依赖；
- [ ] 新建 `BrowserCollector`；
- [ ] 支持正常页面加载、等待明确元素、提取渲染后 DOM；
- [ ] 浏览器采集必须设置超时、并发上限和资源清理。

## P3：任务调度和智能体接口

- [ ] 增加 APScheduler 或 Celery 调度层；
- [ ] 增加周期性公开数据任务；
- [ ] 新建 `app/integrations/`；
- [ ] 定义统一 Agent/API Adapter 协议；
- [ ] 先用一个公开 API 做适配示例，再接实际业务生态。

## Codex 开发原则

1. 每次只完成一组相关功能；
2. 每次修改必须能运行测试；
3. 不把站点特有逻辑写进核心模块；
4. 不实现验证码绕过、登录绕过或访问控制规避；
5. 优先保证任务状态、错误可追踪和结果可复现；
6. 代码复杂度明显上升前，先补接口抽象和测试。
