# 初步开发方案

## 1. 首期开发范围

首期不追求覆盖所有网站，而是先把通用能力做完整：

- 一个统一的任务入口；
- 两种基础采集方式：HTML 页面、JSON 接口；
- 一个可注册的新采集器机制；
- 一个统一的数据结果模型；
- 基础正文清洗与数据去重；
- JSONL 结果存储；
- 任务状态和错误日志；
- API 与命令行两种调用方式。

## 2. 后续扩展方式

新增来源时优先采用“适配器”方式，而不是修改主程序。例如：

- 网站 A：新增 `site_a.py`；
- 网站 B：新增 `site_b.py`；
- 动态页面：接入浏览器采集器；
- 第三方开放平台：新增 API 适配器；
- 智能体平台：新增 Agent Adapter，将其搜索或数据能力统一转换成平台结果格式。

## 3. 智能体生态预留

后续可增加 `app/integrations/agents/` 目录，统一定义：搜索请求、数据请求、返回结果规范、调用日志、限流和错误处理。这样无论接入哪一类智能体或开放平台，对上层任务系统而言都保持一致。

## 4. 风险控制

项目重点控制以下风险：网站结构变化、数据重复、任务失败、数据源差异、规模增长和合规问题。首期保持轻量，后期再接数据库、队列和分布式能力；仅处理授权或公开可访问数据，不设计绕过访问限制的功能。
